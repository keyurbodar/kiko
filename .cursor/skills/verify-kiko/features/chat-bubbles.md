# Chat bubbles

A user reading a Kiko conversation sees one centred column of messages, each in its own rounded bubble: the viewer's on the right in the warm user fill, the agent's on the left in the assistant fill. A one-line bubble is a pill, a longer one has a 16px radius, a run's bubbles meet at a 6px joint, and the run's last bubble carries a tail. The column opens already scrolled to the newest message.

## Sub-features

- `bubble-column`: the transcript is a single column capped at 736px and centred with `margin-inline: auto`, so bubbles never spread across a wide window.
- `bubble-width`: each bubble is `width: fit-content` with a `max-width: min(calc(100% - 3.5rem), 36rem)` cap, so a short message reads as a short bubble and a long one stops growing.
- `bubble-sides`: the user's bubble carries the user fill and the warm bubble text; the agent's carries the assistant fill. They are aligned by `align-self` on the bubble, not by a `justify-content` rule on the row.
- `bubble-run-collapse`: consecutive messages from one sender inside the 300s grouping window render as one run, and only the run's first row gets the extra top padding.
- `bubble-run-break`: a gap over 300 seconds, a change of sender, a change of calendar day, or a message that replies to something all break the run.
- `bubble-tail`: the run's last bubble carries a tail drawn by `::after` in `bubble.css`. The bubbles of a run meet at a 6px joint on the sender's side. A one-line bubble is a pill (18px radius) and a longer one has a 16px radius.
- `bubble-jumbo`: a body of one to three emoji clusters scales up and goes **bare**: split into a single-emoji and a multi-emoji size, with no fill and no padding. Prose is never jumbo.
- `bubble-day-chip`: a sticky floating chip names the day at the top of the viewport, as `Today`, `Yesterday` or a weekday, and opens the calendar. It is visible when a day is at the top of the viewport and no day divider sits in the top 48px.
- `bubble-day-jump`: clicking the chip opens a month calendar; choosing a day scrolls the transcript to that day.
- `bubble-opens-newest`: the transcript arrives pinned to the newest message, not scrolled to the top.
- `bubble-divider`: a day divider sits centred in the column and shows the day's **first message** time, not midnight.
- `bubble-no-border`: no bubble, chip, divider, quote or card draws a border; separation is a fill or a shadow.
- `bubble-no-animation`: nothing in the transcript transitions except the emoji press and the typing wave.
- `chrome-sentence-case`: every label the app draws is in sentence case, as AGENTS.md asks; a message body is never transformed.

## How to get to it (user POV)

- Open `http://localhost:<port>/`. The transcript is the page, with the sidebar down its left edge and the composer docked below it.
- Scroll up and back down to move between days and watch the date chip come and go.
- Click the date chip and pick a day to jump there.
- Read a run of consecutive messages from one sender and watch them sit closer together than two separate runs.

Preconditions:

Selectors this feature relies on. **Bubble geometry is in `chat/ui/bubble.css`, and most of the rest is utilities.** `bubble.tsx` imports `bubble.css`, which sets the bubble radius, the joints and the tail. `chat/typing/typing.css` and `chat/ui/empty-state.css` also exist. `apps/web-solid/src/styles/` holds `app.css`, which declares the `@layer` order and the imports, and `motion.css`. Everything else in the slice is Tailwind utilities on the component that renders the element. (The app's other project-authored stylesheets are `sidebar/sidebar.css` and `composer/composer.css`, and no rule in any of them reaches a bubble.) **Most `.chat-*` classes are QA handles, not style hooks.** `MessageMenu.tsx` says `chat-menu` "is a QA handle as well as the surface". The bubble primitives are `apps/web-solid/src/chat/ui/bubble.tsx` and are reached by `data-slot`; everything else is reached by `data-component`.

## Gotchas

- **There is no stylesheet for the transcript to grep.** Every value in this file is a Tailwind utility on the component that renders the element. A recipe that wants to know where a value comes from reads the component: `chat/ui/bubble.tsx` for the bubble primitives, `chat/ui/MessageRow.tsx` for the row and the run padding, `chat/VirtualThread.tsx` for the column and the divider, and the proof is always the computed value.
- **`data-run` is a tail fact, not a run counter.** Its three values are `start` (first of the run), `mid` (inside it) and `bot` (**last** of it). So a run's final row reads `bot` and is the row that carries the tail, and a single isolated message is both start and end and resolves to `bot`. **Counting `data-run="start"` is therefore not a per-run count**: measured `1` on a three-message run and also `1` on two runs across three rows. Count `data-gap` and `padding-top` instead.
- **Many `.chat-*` classes are QA handles and carry no styling.** `.chat-quote` and its `__body` / `__label` / `__text` / `__thumb`, `.chat-menu` and its `__quick` / `__emoji` / `__more` / `__picker` / `__danger`, `.chat-empty-title`, `.chat-fades__top` / `__bottom`, and `.chat-calendar` and its `__title` / `__day` all exist so a probe can find the element. The components say so in their own comments. Assert the computed value directly; never conclude a value holds "because the class is applied".
- **The bubble radius is a token, and a one-line bubble is a pill.** The content uses `rounded-(--bubble-r)`, which `bubble.css` sets to 16px. On a one-line bubble the pill rule sets it to half the line height plus the vertical padding, which is 18px. The day chip's open panel uses `calc(20px * var(--brm))`. `--brm` is `0.5` by default and `1` under `@supports (corner-shape: squircle)`, and **on this machine `CSS.supports("corner-shape", "squircle")` is `true` and `--brm` resolves to `1`**, so the idiom renders its full value. Assert each component's radius against the token and the browser's own `CSS.supports` answer, not a hard-coded number.
- **The transcript is virtualized.** `document.querySelectorAll('[data-component="chat-vrow"]').length` tracks the viewport, not the message count, and an element captured before a scroll can be detached by the time you act on it. Re-query immediately before every measurement, and never compare a row count against the room's message total.
- **The scroller is `[data-component="chat-scroll"]`, not the window.** `window.scrollTo` moves nothing. Write `scrollTop` on the scroller, and move it to a value it does not already hold: assigning the same value fires no scroll event, so anything driven by scroll silently does not update. And a written `scrollTop` is not a user scroll, so prefer `page.mouse.wheel` where the recipe cares about scroll-derived state.
- **The bubble cap is measured against the row's content box, not the column or the window.** The row is itself capped at 736px and carries 16px of side padding, so the content box is 704px and the cap lands at 576px, not a share of the shell. Measured against the surface it reports a false failure on a narrow window and a false pass on a wide one.
- **The bubble's box is a parent and a painted child, and only the child has a surface.** `[data-slot="bubble"]` is the positioned parent, `relative flex w-fit min-w-0 max-w-[min(calc(100%-3.5rem),36rem)] flex-col gap-1`, with `data-[align=end]:self-end`, with no padding, no background and no radius. `[data-slot="bubble-content"]` is the painted, clipping surface. Read padding, radius, fills and the jumbo sizes off the child, and `max-width` and `width` off the parent. The parent also holds the absolutely placed hover actions, `[data-component="chat-actions"]`.
- **Horizontal alignment is the bubble's `align-self`, not the row's `justify-content`.** `[data-component="chat-row"]` is `flex flex-col items-start`, and `data-[align=end]:self-end` on the bubble is what pins it to `flex-end`. There is no `[data-side]`-keyed `justify-content` rule to find, so a side probe that reaches for one is reading a rule that no longer exists.
- **A message with attachments keeps the bubble's padding.** Its pictures and file rows sit inside the content's own `padding`, above the text with an 8px gap, as t3code draws them. So `padding: 8px 12px` holds for every bubble, attachments or not. See [Message attachments and the image dialog](./chat-images.md).
- **An unlayered rule silently beats every utility, and margin was the casualty.** A bare `* { margin: 0 }` in `kat.css` used to sit outside any layer, and an unlayered rule outranks every `@layer` regardless of specificity, so it beat Tailwind's `@layer utilities` and **every margin utility in the app was dead**: `mx-auto` computed to `0px` and the 736px transcript column sat pinned to the left edge. It is now inside `@layer base`. Assert that a margin utility *resolves* (the column's `margin-left` is a pixel value equal to `(stage - 736) / 2`), see [Kat token layer](./kat-tokens.md).
- **`--font-base` is 14px on `body`; the root is 16px.** A rem-based measurement of bubble padding or font size reads 0.875x too small if you resolve it against the root. Read the computed `font-size` off the element itself.
- **The chip is hidden with `display: none`, not with opacity.** Assert the anchor's `data-visible` or the computed `display`; a `querySelector` that only checks for existence finds a chip that is not on screen.
- **`auto` margins resolve during layout, so they never come back as `auto`.** `getComputedStyle(col).marginInlineStart` on the centred column is a pixel value, not the keyword. Compare `left` against `(stage - 736) / 2` instead of looking for the keyword.
- **`--radius-sm` reads as an empty string on `:root`.** It is declared in Tailwind's `@theme` block and the compiler emits that as its own `:root` rule, so a root read returns `""` while `--radius-bubble` returns `16px` on the same read. Read a radius off a component's computed `border-radius`.
- **The chat fixture harness is gone.** The old `/src/chat/harness.html` page was removed in 2026-11; every recipe here runs on the composed app at `/`, which mounts the transcript, the composer, and the sidebar together.
- **Geometry measured in a fallback face is not a measurement.** Nothing here depends on a font beyond the token layer, but wait for `document.fonts.ready` before reading sizes: see [Kat token layer](./kat-tokens.md).
