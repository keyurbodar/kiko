# Chat bubbles

A user reading a Kiko conversation sees one centred column of messages, each in its own rounded bubble: the viewer's on the right in the warm user fill, the agent's on the left in the assistant fill. Every bubble keeps the same full radius — there is no run tail — and the column opens already scrolled to the newest message.

## Sub-features

- `bubble-column` — the transcript is a single column capped at 768px and centred with `margin-inline: auto`, so bubbles never spread across a wide window.
- `bubble-width` — each bubble is `width: fit-content` with a `max-width: 80%` cap, so a short message reads as a short bubble and a long one stops growing.
- `bubble-sides` — the user's bubble carries the user fill and the warm bubble text; the agent's carries the assistant fill. They are aligned by `align-self` on the bubble, not by a `justify-content` rule on the row.
- `bubble-run-collapse` — consecutive messages from one sender inside the 300s grouping window render as one run, and only the run's first row gets the extra top padding.
- `bubble-run-break` — a gap over 300 seconds, a change of sender, a change of calendar day, or a message that replies to something all break the run.
- `bubble-no-tail` — every bubble keeps the full 18px radius. kat ships exactly one bubble radius and no per-run corner clamp, so consecutive messages are identical pills rather than a stack with a tail.
- `bubble-jumbo` — a body of one to three emoji clusters scales up and goes **bare**: split into a single-emoji and a multi-emoji size, with no fill and no padding. Prose is never jumbo.
- `bubble-day-chip` — a sticky floating chip names the day at the top of the viewport, in lowercase, and opens the calendar. It is visible whenever there is a top visible day, whatever day that is.
- `bubble-day-jump` — clicking the chip opens a month calendar; choosing a day scrolls the transcript to that day.
- `bubble-opens-newest` — the transcript arrives pinned to the newest message, not scrolled to the top.
- `bubble-divider` — a day divider sits centred in the column and shows the day's **first message** time, not midnight.
- `bubble-no-border` — no bubble, chip, divider, quote or card draws a border; separation is a fill or a shadow.
- `bubble-no-animation` — nothing in the transcript transitions except the emoji press and the typing wave.
- `chrome-lowercase` — every label the app draws is lowercase; a message body is never transformed.

## How to get to it (user POV)

- Open `http://localhost:<port>/`. The transcript is the page, with the sidebar down its left edge and the composer docked below it. There is no top bar and no router, so this is the only entry point a user has.
- Scroll up and back down to move between days and watch the date chip come and go.
- Click the date chip and pick a day to jump there.
- Read a run of consecutive messages from one sender and watch them sit closer together than two separate runs.

## Driving it with ego-browser

Preconditions:

- The dev server is running on the port chosen in `../../SKILL.md` and `/tmp/kiko-verify-evidence/vite.pid` names it.
- `../../SKILL.md` **Doctor** reports `ok: true` and `harnessStatus: 200`.
- **Use `http://localhost:<port>/`, not `http://127.0.0.1:<port>/`.** The server binds IPv6 loopback only; `curl` to `127.0.0.1:3017` exits `7` (connection refused) while `localhost:3017` answers `200`.
- **Every `page.goto` passes `{ waitUntil: "domcontentloaded", timeout: 60000 }`.** The transcript's media never finishes loading, so the default `load` wait never fires and the default 15s deadline rejects on a healthy page.
- For every fixture state below, drive `http://localhost:<port>/src/chat/harness.html?state=<slug>`, then `page.waitForFunction(() => typeof window.__chat === "object", undefined, { timeout: 15000 })`, and confirm `window.__chat.probe().state` matches the state before measuring. Use `page.evaluate((slug) => window.__chat.setState(slug), "<slug>")` to move between states in one round; an unknown slug falls back to `today` and says so in `[data-component="harness-state"]`, so check that too.

Selectors this feature relies on. **The transcript has no stylesheet to read.** `apps/web-solid/src/styles/` contains exactly one file, `app.css`, which is a `@layer` order declaration and four `@import` lines; the chat slice is Tailwind utilities on the component that renders the element. (The app's other project-authored stylesheets are `sidebar/sidebar.css` and `composer/composer.css`, and no rule in any of them reaches a bubble.) **A `.chat-*` class is a QA handle, not a style hook** — the components say so in their own comments, e.g. `.chat-chip-anchor` "is a handle, not a style" and `.chat-chip` "is a QA handle, not a style". The bubble primitives are `apps/web-solid/src/chat/ui/bubble.tsx` and are reached by `data-slot`; everything else is reached by `data-component`.

  - Write `{ matchCount, violations, allowed }` to `/tmp/kiko-verify-evidence/no-animation.json`. `violations` is empty for every surface: `transitionDuration` is `0s` and `animationName` is `none` across the board, measured on the same eight states as the border probe. The only rows allowed to carry a name are the press on a quick strip emoji button and a reaction badge, and the typing dots' wave. Picker and popover cells do not move.   - **The probe is scoped to the transcript, and the sidebar is not in it.** `[data-component="sidebar"]` mounts only in the composed app, so a sidebar element in a violation list means the scope leaked.
  - The menu and the picker render in a portal outside the column, so a scope that stops at `[data-component="chat-column"]` misses them. The jump pill and the scroll scrims float on the stage rather than scrolling with it, so they must be in the pass too.

- **Every label is lowercase; no body is transformed.** Observe: chrome labels compute `lowercase` and message bodies compute `none`.
  - Run one `page.evaluate` mapping `.chat-chip`, `.chat-empty__text`, `.chat-unread__label`, `.chat-calendar__title`, the menu's action buttons, `[data-component="chat-day-label"]`, `[data-component="chat-day-time"]` and every `.chat-text` body, to `{ role, sample: textContent?.slice(0, 40), textTransform: getComputedStyle(node).textTransform }`.

Run this against a fixture body that starts with a capital letter: a `capitalize` transform would be invisible on an all-lowercase body and is the reason the assertion reads computed style rather than trusting the source.

## Gotchas

- **There is no stylesheet for the transcript to grep.** Every value in this file is a Tailwind utility on the component that renders the element. A recipe that wants to know where a value comes from reads the component — `chat/ui/bubble.tsx` for the bubble primitives, `chat/ui/MessageRow.tsx` for the row and the run padding, `chat/VirtualThread.tsx` for the column and the divider — and the proof is always the computed value.
- **`data-run` is a tail fact, not a run counter.** Its three values are `start` (first of the run), `mid` (inside it) and `bot` (**last** of it). So a run's final row reads `bot` and carries no distinguishing style, and a single isolated message is both start and end and resolves to `bot`. **`probe().runs` counts `data-run="start"` and is therefore not a per-run count**: measured `1` for `grouped` (one run of three) and also `1` for `run-gap` (two runs across three rows). Count `data-gap` and `padding-top` instead.
- **Many `.chat-*` classes are QA handles and carry no styling.** `.chat-text`, `.chat-quote` and its `__body` / `__label` / `__text` / `__thumb`, `.chat-row-time`, `.chat-menu` and its `__quick` / `__emoji` / `__more` / `__picker` / `__danger`, `.chat-empty__text`, `.chat-unread__label`, `.chat-fades__top` / `__bottom`, `.chat-calendar` and its `__title` / `__day`, and the `harness-*` set all exist so a probe can find the element. The components say so in their own comments. Assert the computed value directly; never conclude a value holds "because the class is applied".
- **There is exactly one bubble radius, and no tail.** `rounded-bubble` is the only radius on a message bubble; kat ships one bubble radius and no per-run corner clamp. The transcript's other radii are literals — the chip's open panel 15px, the quote `calc(var(--radius-bubble) - 7px)`. The menu, the picker's surfaces and the typing bubble use the `calc(Npx * var(--brm))` idiom. `--brm` is `0.5` by default and `1` under `@supports (corner-shape: squircle)`, and **on this machine `CSS.supports("corner-shape", "squircle")` is `true` and `--brm` resolves to `1`**, so the idiom renders its full value. Assert each component's radius against the token and the browser's own `CSS.supports` answer, not a hard-coded number.
- **The transcript is virtualized.** `document.querySelectorAll('[data-component="chat-vrow"]').length` tracks the viewport, not the message count, and an element captured before a scroll can be detached by the time you act on it. Re-query immediately before every measurement, and never compare a row count against a fixture's message total.
- **The scroller is `[data-component="chat-scroll"]`, not the window.** `window.scrollTo` moves nothing. Write `scrollTop` on the scroller, and move it to a value it does not already hold — assigning the same value fires no scroll event, so anything driven by scroll silently does not update. And a written `scrollTop` is not a user scroll, so prefer `page.mouse.wheel` where the recipe cares about scroll-derived state.
- **The 80% cap is measured against the row's content box, not the column or the window.** The row is itself capped at 768px and carries 16px of side padding, so the cap lands at 588.8px, not 614px and not a share of the shell. Measured against the surface it reports a false failure on a narrow window and a false pass on a wide one.
- **The bubble's box is a parent and a painted child, and only the child has a surface.** `[data-slot="bubble"]` is the positioned parent — `relative flex w-fit min-w-0 max-w-[80%] flex-col gap-1`, with `data-[align=end]:self-end` — with no padding, no background and no radius. `[data-slot="bubble-content"]` is the painted, clipping surface. Read padding, radius, fills and the jumbo sizes off the child, and `max-width` and `width` off the parent. The parent also holds the absolutely placed hover actions, `[data-component="chat-actions"]`.
- **Horizontal alignment is the bubble's `align-self`, not the row's `justify-content`.** `[data-component="chat-row"]` is `flex flex-col items-start`, and `data-[align=end]:self-end` on the bubble is what pins it to `flex-end`. There is no `[data-side]`-keyed `justify-content` rule to find, so a side probe that reaches for one is reading a rule that no longer exists.
- **A message with attachments keeps the bubble's padding.** Its pictures and file rows sit inside the content's own `padding`, above the text with an 8px gap, as t3code draws them. So `padding: 7px 12px` holds for every bubble, attachments or not. See [Message attachments and the image dialog](./chat-images.md).
- **An unlayered rule silently beats every utility, and margin was the casualty.** A bare `* { margin: 0 }` in `kat.css` used to sit outside any layer, and an unlayered rule outranks every `@layer` regardless of specificity — so it beat Tailwind's `@layer utilities` and **every margin utility in the app was dead**: `mx-auto` computed to `0px` and the 768px transcript column sat pinned to the left edge. It is now inside `@layer base`. Assert that a margin utility *resolves* (measured: the column's `margin-left` is `326px` on the harness and `156px` on the composed app, and a `div.mx-auto` probe computes to `660px`) — see [Kat token layer](./kat-tokens.md).
- **`--font-base` is 14px on `body`; the root is 16px.** A rem-based measurement of bubble padding or font size reads 0.875x too small if you resolve it against the root. Read the computed `font-size` off the element itself.
- **The chip is hidden with `display: none`, not with opacity.** Assert the anchor's `data-visible` or the computed `display`; a `querySelector` that only checks for existence finds a chip that is not on screen.
- **`auto` margins resolve during layout, so they never come back as `auto`.** `getComputedStyle(col).marginInlineStart` on the centred column is a pixel value, not the keyword. Compare `left` against `(stage - 768) / 2` instead of looking for the keyword.
- **`--radius-sm` reads as an empty string on `:root`.** It is declared in Tailwind's `@theme` block and the compiler emits that as its own `:root` rule, so a root read returns `""` while `--radius-bubble` returns `18px` on the same read. Read a radius off a component's computed `border-radius`.
- **The harness is a page, not a route.** `/src/chat/harness.html` is a Vite multi-page entry; it is not in the app's router, and a 404 on any other sub-path is expected. It mounts `MessageList` alone — **no composer, no sidebar, and no send path** — so `[data-component="chat-shell"]`, `[data-component="composer-dock"]` and `[data-component="sidebar"]` are all `0` there.
- **Geometry measured in a fallback face is not a measurement.** Nothing here depends on a font beyond the token layer, but wait for `document.fonts.ready` before reading sizes — see [Kat token layer](./kat-tokens.md).
