# Chat bubbles

A user reading a Kiko conversation sees one centred column of messages, each in its own rounded bubble: the viewer's on the right in the warm user fill, the agent's on the left in the assistant fill. Every bubble keeps the same full radius — there is no run tail — and the column opens already scrolled to the newest message.

## Sub-features

- `bubble-column` — the transcript is a single column capped at 768px and centred with `margin-inline: auto`, so bubbles never spread across a wide window.
- `bubble-width` — each bubble is `width: fit-content` with a `max-width: 80%` cap, so a short message reads as a short bubble and a long one stops growing.
- `bubble-sides` — the user's bubble carries the user fill and the warm bubble text; the agent's carries the assistant fill.
- `bubble-run-collapse` — consecutive messages from one sender inside the grouping window render as one run, and only the run's first row gets the extra top padding.
- `bubble-run-break` — a gap over 300 seconds, a change of sender, a change of calendar day, or a message that replies to something all break the run.
- `bubble-no-tail` — every bubble keeps the full radius. kat ships exactly one bubble radius and no per-run corner clamp, so consecutive messages are identical pills rather than a stack with a tail.
- `bubble-jumbo` — a body that is one to three emoji clusters scales up, split into a single-emoji and a multi-emoji size; prose is never jumbo.
- `bubble-day-chip` — a sticky floating chip names the day at the top of the viewport, in lowercase, and opens the calendar. It is visible whenever there is a top visible day, whatever day that is.
- `bubble-day-jump` — clicking the chip opens a month calendar; choosing a day scrolls the transcript to that day.
- `bubble-opens-newest` — the transcript arrives pinned to the newest message, not scrolled to the top.
- `bubble-no-border` — no bubble, chip, divider, quote or card draws a border; separation is a fill or a shadow.
- `bubble-no-animation` — nothing transitions except the swipe snap-back, the emoji press, and the typing wave.
- `chrome-lowercase` — every label the app draws is lowercase; a message body is never transformed.

## How to get to it (user POV)

- Open `http://127.0.0.1:3001/`. The transcript is the page. There is no sidebar, no top bar, and no router, so this is the only entry point a user has.
- Scroll up and back down to move between days and watch the date chip come and go.
- Click the date chip and pick a day to jump there.

## Gotchas

- **There is no stylesheet to grep.** Every value in this file is a Tailwind utility on the component that renders the element, and `apps/web-solid/src/styles/app.css` is three `@import` lines and nothing else. A recipe that wants to know where a value comes from reads the component — `apps/web-solid/src/chat/ui/bubble.tsx` for the bubble primitives, `apps/web-solid/src/chat/ui/MessageRow.tsx` for the row and the run padding, `apps/web-solid/src/chat/VirtualThread.tsx` for the column and the divider — and the proof is always the computed value, never the source.
- **Many `.chat-*` classes are QA handles and carry no styling.** `.chat-text`, `.chat-quote` and its `__body` / `__label` / `__text` / `__thumb`, `.chat-link-card`, `.chat-row-time`, `.chat-empty` and `__text`, `.chat-unread-slot`, `.chat-unread-clip`, `.chat-unread`, `.chat-unread__label`, `.chat-chip-anchor`, `.chat-chip`, `.chat-calendar` and its `__title` / `__day`, `.chat-jump-latest`, `.chat-jump` and the `harness-*` set all exist only so a probe can find the element. Assert the computed value directly; never conclude a value holds "because the class is applied".
- **There is exactly one bubble radius, and no tail.** `rounded-bubble` is the only radius on a message bubble; kat ships one bubble radius and no per-run corner clamp, and the grouped stacks show twelve consecutive messages as twelve identical pills. The transcript's other radii are literals — the chip 15px, the quote `calc(var(--radius-bubble) - 7px)`. The menu 20px, the picker 16px, its search 10px, its cell 8px and the typing bubble 18px use the `calc(Npx * var(--brm))` idiom, which matches kat's own reference stylesheets. `--brm` is `0.5` by default and `1` under `@supports (corner-shape: squircle)`, so those five read half their nominal value on a browser that cannot draw a continuous corner. **A halved menu or picker corner is the token system working, not drift — do not "fix" it.** A halved *bubble* would be drift, because the transcript is on literals.
- **The transcript is virtualized.** `document.querySelectorAll('[data-component="chat-vrow"]').length` tracks the viewport, not the message count, and an element captured before a scroll can be detached by the time you act on it. Re-query immediately before every measurement, and never compare a row count against a fixture's message total.
- **The scroller is `[data-component="chat-scroll"]`, not the window.** `window.scrollTo` moves nothing. Write `scrollTop` on the scroller, and move it to a value it does not already hold — assigning the same value fires no scroll event, so anything driven by scroll silently does not update.
- **The 80% cap is measured against the row's content box, not the column or the window.** The row is itself capped at 768px and carries 16px of side padding, so the cap lands at 588.8px, not 614px and not a share of the shell. Measuring against the surface reports a false failure on a narrow window and a false pass on a wide one.
- **The typing bubble is the one place the two conventions disagree.** `[data-component="chat-typing-bubble"]` asks for 18px through the idiom while `[data-slot="bubble-content"]` asks for the same 18px as a literal, so on a browser without squircle the typing bubble reads a few pixels rounder than the message bubbles beside it. The interaction owner has flagged it; until it is settled, read it against the token and do not report the difference as a defect.
- **The bubble's box is a parent and a painted child, and only the child has a surface.** `[data-slot="bubble"]` is the positioned parent — `relative flex w-fit min-w-0 max-w-[80%] flex-col gap-1`, with `data-[align=end]:self-end` and the swipe transform written as `[&>[data-slot=bubble]]:translate-x-(--swipe-x)` on the row — with no padding, no background and no radius. `[data-slot="bubble-content"]` is the painted, clipping surface: `px-3 py-[7px] rounded-bubble overflow-hidden wrap-break-word`, with the fill and text colour selected by the parent's `data-variant`. Read padding, radius, fills and the jumbo sizes off the child, and `max-width`, `width` and the transform off the parent. `white-space: pre-wrap` is not on the child — it stays on `.chat-text` in `apps/web-solid/src/chat/ui/LinkText.tsx`. Both halves are in `apps/web-solid/src/chat/ui/bubble.tsx`; the row adds the jumbo sizes and the run padding, and nothing else — a reaction changes no geometry at all.
- **Horizontal alignment is the bubble's `align-self`, not the row's `justify-content`.** `[data-component="chat-row"]` is `flex flex-col items-start`, and `data-[align=end]:self-end` on the bubble is what pins it to `flex-end`. There is no `[data-side]`-keyed `justify-content` rule to find, so a side probe that reaches for one is reading a rule that no longer exists.
- **An unlayered rule silently beats every utility, and margin was the casualty.** Section 7 of `packages/ui/src/styles/kat.css` used to carry a bare `* { margin: 0 }`, and an unlayered rule outranks every `@layer` regardless of specificity — so it beat Tailwind's `@layer utilities` and **every margin utility in the app was dead**: `mx-auto` computed to `0px` and the 768px transcript column sat pinned to the left edge. It is now inside `@layer base`, alongside the preflight. Padding was never affected, because the preflight that zeroes it is already in `base`. Assert that a margin utility *resolves* — see [Kat token layer](./kat-tokens.md) — and never author an unlayered rule in these stylesheets.
- **`--font-base` is 14px on `body`; the root is 16px.** A rem-based measurement of bubble padding or font size reads 0.875x too small if you resolve it against the root. Read the computed `font-size` off the element itself.
- **The chip is hidden with `display: none`, not with opacity.** Assert the anchor's `data-visible` attribute or the chip's computed `display`; a `querySelector` that only checks for the element's existence finds a chip that is not on screen.
- **Setting `scrollTop` is not a user scroll.** A jump driven by writing the offset skips the scroll events a wheel would fire, so state that tracks *how* the reader arrived — the chip's `data-visible` among it — can differ. Where the recipe cares about that, use `page.mouse.wheel` over the scroller instead.
- **The harness is a page, not a route.** `/src/chat/harness.html` is a Vite multi-page entry; it is not in the app's router, and a 404 on any other sub-path is expected.
