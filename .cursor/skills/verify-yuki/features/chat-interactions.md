# Chat interactions

Everything a reader can do to a message: open its menu, use its hover actions, react to it, follow a reply back to what it answers, and see who is typing. The transcript is a conversation, not a document — the same message responds the same way whether the viewer wrote it or the agent did, with one exception the menu makes visible.

## Sub-features

- `menu-right-click` — right-clicking any message opens a menu. Today the same two actions are offered on both sides; the `edit` entry exists in the component and is **not rendered for the agent's messages**, and `pin` / `delete` exist but are omitted while no store mutation backs them.
- `hover-actions` — on a pointer device, hovering a row (or giving it keyboard focus) shows three 32px round buttons beside the bubble, vertically centered on it: react, reply and "…". They sit right of an agent's bubble and left of the viewer's. Touch devices never show them; there is no swipe to reply.
- `reaction-popover` — hovering the react button for about 120ms (or clicking it, or Enter) opens a 24px-radius panel of 13 recent emoji in two rows of seven, with "…" last. "…" swaps in the full picker. The panel stays open while the pointer crosses from the button into it.
- `reactions-toggle` — a message carries **one chip per emoji**, never one reaction overall. Each chip toggles on its own, so reacting with a second emoji ADDS a chip rather than replacing the first. The viewer is at most one reactor on any chip: the chip they are on carries `aria-pressed="true"`, and toggling never moves anyone else's chip.
- `reaction-badge` — one 28px circle per emoji, in a positioned row that sits outside the bubble's corner, drawn with a shadow ring rather than a border, and costing no layout.
- `reply-quote` — a reply's quote is the bubble's first **block**: the quoted sender's name is the label, clamped to one line, and the quoted text is clamped to two.
- `reply-quote-thumb` — a quote whose parent carries an image shows a 32px thumbnail beside the text, and only that quote lays out as a row.
- `reply-jump` — clicking the quote scrolls the transcript to the message it answers.
- `unread-rule` — a rule sits before the first unread incoming message, is never the last row, and collapses out of the layout when it retires.
- `picker-takeover` — the picker replaces the menu's quick strip and actions entirely.
- `emoji-picker` — yuki's own picker: a search pill, then "Recently used" and the emojibase groups as 8-column grids of the platform's own glyphs. Arrow keys move from the search field, Enter picks, Escape is the caller's.
- `typing-bubble` — typing renders as an in-list bubble of three dots with no avatar and no visible label; the label is announced to screen readers instead.

## How to get to it (user POV)

- Right-click any message, yours or the agent's, to open its menu.
- Hover any bubble to show react, reply and "…" beside it. Hover react to get the quick reactions; "…" opens the message menu at the button.
- Click a reaction badge to add or remove your own reaction.
- Click the quoted block at the top of a reply to jump back to the message it answers.
- Right-click a message, then click the `+` at the end of the quick strip, to open the emoji picker and search it. Or hover react and click the popover's "…".
- Send a message to watch the typing bubble appear for whoever is replying, and the unread rule retire.

## Driving it with ego-browser

Preconditions:

- The dev server is running on the port chosen in `../../SKILL.md` and `/tmp/yuki-verify-evidence/vite.pid` names it.
- `../../SKILL.md` **Doctor** reports `ok: true` and `harnessStatus: 200`.
- **Use `http://localhost:<port>/`, not `http://127.0.0.1:<port>/`.** The Vite server binds IPv6 loopback only; `curl` to `127.0.0.1:3017` exits `7` (connection refused) while `localhost:3017` answers `200`.
- **Every `page.goto` passes `{ waitUntil: "domcontentloaded", timeout: 60000 }`.** The transcript's media never finishes loading, so the default `load` wait never fires and the driver's 15s deadline rejects on a healthy page. The rejection text names `domcontentloaded` even when you did not ask for it; the navigation did commit.
- **`page.on` does not exist** (`typeof page.on === "undefined"`), so console and uncaught-error capture goes through `page.cdp("Page.addScriptToEvaluateOnNewDocument", { source })` registered **before** navigation, then read with `page.evaluate`.
- Drive `http://localhost:<port>/src/chat/harness.html?state=<slug>`, wait for `page.waitForFunction(() => typeof window.__chat === "object", undefined, { timeout: 15000 })`, and confirm `probe().state` before measuring.
- A **message id** for `openMenu` / `openPicker` / `setReplyTarget` is `document.querySelector("[data-component='chat-row']").dataset.messageId`, read from the DOM immediately before each call. A row index is not an id: the transcript renumbers as it scrolls.
- **`openMenu` and `openPicker` return what happened, they do not guarantee it.** `openMenu` dispatches a real `contextmenu` and reports `true`; **read the boolean AND `probe().overlay` before trusting a DOM read**, because a stale overlay left in the document makes a no-op look like an open menu. Close with `page.keyboard.press("Escape")` and confirm `probe().overlay` is `null` before the next open.
- **`openPicker` opens the menu, clicks `.chat-menu__more`, and waits for `[data-component='emoji-picker']`.** Read its boolean and `probe().overlay` as for `openMenu`.
- Every recipe here is virtualized. Re-query the target immediately before each action, because a scroll detaches rows.

Selectors this feature relies on. **There is no stylesheet for the transcript** — the chat slice is Tailwind utilities on the component that renders the element, plus the token layer. **A `.chat-*` class is a QA handle, not a style hook.** The menus and pickers portal out of the column, so scope them by their own attributes, never by a bubble or column ancestor.

## Gotchas

- **Scope the menu by `.chat-menu` or `[data-component="menu-v2-content"]`, never by `[data-component="chat-menu"]`.** `MenuV2.Context.Content` overwrites the `data-component` prop with its own, so the attribute never reaches the DOM — measured `0` by component, `1` by class, with the menu visibly open. The same applies to any other `data-component` handed to a v2 component as a prop.
- **Menus and pickers portal out of the column.** Never scope them by a bubble or column ancestor. A portalled menu is also a common source of a stray non-zero `transition-duration`; the no-animation probe in [Chat bubbles](./chat-bubbles.md) must include it.
- **`openMenu`, `openPicker`, `openMedia` and `closeMedia` return whether a dialog actually opened, and the test is not always right.** `openMenu` tests `[role='menu'], [data-component*='menu']`, which matches `menu-v2-content` — so it is reliable here. `openPicker` waits for `[data-component='emoji-picker']` and is reliable. `openMedia` / `closeMedia` and `probe().viewer` test `[data-component="image-dialog"]`, the image dialog's inner column; `openMedia` is async and waits up to a second for the lazy dialog. **A `false` is a finding about the probe first.** Read the DOM for yourself before concluding anything is broken.
- **The menu's own trigger is not a thing to click.** `.chat-menu__trigger` is a zero-size `position: fixed` anchor that only receives a replayed `contextmenu` so Kobalte's positioning has something to anchor to. It is never visible and never hittable; asserting anything about it is a dead end. Drive the menu with `openMenu` or a real right-click.
- **The menu's quick strip is buttons, not menu items.** `[role="menuitem"]` and `[data-component="menu-v2-item"]` both miss the emoji buttons, so a recipe that counts menu items undercounts by six. Read the emoji strip and the action list separately.
- **`pin`, `edit` and `delete` are not rendered today, on either side.** `VirtualThread` builds the menu without those callbacks because no store mutation backs them, and the component omits an item whose handler is undefined. Do not write a recipe that expects them, and do not report their absence as a gap — report an `edit` on the **agent's** menu, which is the one the component actively guards against.
- **There is no swipe to reply.** It was removed. Reply comes from the hover actions, the menu, or the quote. On touch, the menu is the route.
- **The hover actions are `display: none` on a coarse pointer.** A touch-emulated browser reports them absent, and that is correct.
- **The typing label is in the DOM but not on screen.** It lives in an `.sr-only` span inside the typing row, so any assertion based on `textContent` alone reports a visible label that is not there. Walk the text nodes and exclude `.sr-only`, or assert the row's rendered geometry instead.
- **The typing wave is inline, not a CSS keyframe.** `animationName` is `none` and the transform and opacity are written onto the element's `style`. A probe that asserts a keyframe name reports a working indicator as broken.
- **The typing row is a direct child of the column, not of a virtual row.** `row.closest('[data-component="chat-vrow"]')` is `null`; the parent chain is `chat-typing-row → chat-column → chat-scroll → chat-stage`. Assert the column ancestor, not the vrow.
- **Emoji are system glyphs.** There is no Twemoji artwork and no `/emoji/*.svg`. A badge, a picker cell or a jumbo message holds the emoji as text in a `font-emoji` element.
- **A message carries one chip per emoji, never one reaction overall — so "a count that only grows" is the wrong failure to look for.** The real failures are a *second* chip appearing for the SAME emoji on a message that already has one, and a swap that adds rather than replaces. Toggle the same badge twice and compare all three readings each time, and separately pick a *different* emoji and assert the chip count goes UP to two chips with a new `data-emoji` — not that it stays at one.
- **Measure `chips[0]`, not the visually-first chip, and do not branch on `data-align`.** For `align="end"` the row is `flex-row-reverse`, so `chips[0]` is both DOM-first and visually last.
- **Assert the chip's horizontal overhang as `18`, not kat's `12`.** Twelve left the badge's inner edge inside the text and clipped the first letter of a one-line message. A run that checks against 12 reports a correct implementation as drift.
- **The quote clamps to two lines, not one, and it is nested one level down.** The label is a one-line ellipsis and the quoted text is a two-line clamp; read both in one pass. The quote is a child of a wrapper div inside the bubble content, so `content.firstElementChild === quote` is `false` by design.
- **The quote's label names the QUOTED sender, resolved through the roster** — `you` for the viewer, the agent's name for an agent — never the carrying row's own sender.
- **The reaction toggle cannot be proven in the harness.** The harness renders a static fixture array while `onReact` mutates a store nothing is displaying, so the DOM never moves. Prove it at `/`, and never report a dead chip in the harness as an app defect.
- **`bun test` resolves `solid-js` to its server build**, where `createMemo` never re-runs. A unit test that derives state with `createMemo` will pass on a stale value and prove nothing. Anything derived belongs in these browser recipes.
- **Geometry measured in a fallback face is not a measurement.** Wait for `document.fonts.ready` before reading sizes — see [Kat token layer](./kat-tokens.md).
