# U65 Memory capture never stalls on a big batch

**Model** Claude Haiku 5.5 medium. **Wave** 7. **Timebox** 75 min. **Port** 8865.

Source: review D finding D1 (`issues/review/D.md`).

## Do

In `apps/server/src/user/memory-capture.ts` (`captureNow`, around 176-197), the judge path sends every queued row (up to 24) in one classify call with an 8 s timeout. A timeout keeps the same rows at the head of the queue, so capture stalls for that user. Judge rows in chunks of about 4, dequeue each chunk that succeeds, and leave only a failed chunk queued. Keep the rest of the contract unchanged. Do not change the judge questions in this unit (the reviewer's second step changes the judge contract; leave it).
