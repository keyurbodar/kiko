
## Report

Fixed end to end: reply (bubble button, composer card, `replyTo` routing through replies, server `reply` preview with `gone`, quote jump by `seq` for an unloaded original), the send gate (no model or broken provider disables Send with a reason and actions, nothing optimistic), and run failures (private `run_error` line with fixed sentences and Retry / Change model / Open settings, a `model` error frame with `roomId` so the toast shows only when the human is elsewhere, `retry.enabled=false`, `retry` frame re-delivering the same inputs). `run_error` frame and `no_provider` event are gone; R25's coordinator is the only toast path. A failed turn never posts bubble text (`outbox.ts`); `[model-error]` is only a dev fake-agent trigger the human types.

Docs: architecture sections 6.1, 6.2.1 (new), 9.4. Budget: tier 1 re-recorded to 2506 (lazy chunk name in the entry); tiers 2 to 4 within limits.

Tests that failed on base c2fc8fdd: reply-preview, retry-run, recipients, run-error, stall, run-error-bubbles (server); send-block, reply (quoteOf), event-line, errors (seenInChat) (client).

## Discoveries

- pi-durable's default retry (3 tries, growing delay) kept agents typing about 15 s after an error.
- The old reply routing only knew agent authors, so replies to the human's own messages reached nobody.
