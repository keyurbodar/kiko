# R34: zero-friction first install

## Research (developers.cloudflare.com only)

- **Can R2 be enabled through the API?** No documented way. The R2 get-started page says "You need a Cloudflare account with an R2 subscription" and sends the owner through checkout (https://developers.cloudflare.com/r2/get-started/). The create-bucket reference lists no activation call and only the `Workers R2 Storage Write` permission (https://developers.cloudflare.com/api/resources/r2/subresources/buckets/methods/create/). The tokens page says R2 must be purchased before a token is made (https://developers.cloudflare.com/r2/api/tokens/). Whether a card is required is not stated; the pricing page lists a free tier of 10 GB-month, 1M class A and 10M class B operations (https://developers.cloudflare.com/r2/pricing/).
- **Error codes** (https://developers.cloudflare.com/r2/api/error-codes/): 10042 `NotEntitled` (403, "Account not entitled to this feature"), 10073 `BucketConflict` (409, exists; the old code looked for 10004, which is not in the table), 10009 too many buckets.
- **OAuth scopes.** Names follow the API token permission names, and the full list is `GET /client/v4/oauth/scopes` with a token (https://developers.cloudflare.com/fundamentals/oauth/create-an-oauth-client/). The request may not carry a scope the OAuth client lacks. Every call the installer makes is covered by the three scopes it already asks for, so none is added.
- **Free Durable Objects** (https://developers.cloudflare.com/durable-objects/platform/limits/, .../pricing/): SQLite-backed only; 5 GB total storage; 2 MB a value or row; 100 bound parameters; 100,000 rows written and 5,000,000 rows read a day. The limits page contradicts itself on per-object storage (10 GB in the table, 1 GB on Free in the FAQ).
- **Workers Free** (https://developers.cloudflare.com/workers/platform/limits/): 50 subrequests, 10 ms CPU, 100 Workers, 100 MB request body.

## First-run failure modes for a brand-new account

| # | Failure | Handled |
| --- | --- | --- |
| 1 | No workers.dev subdomain (https://developers.cloudflare.com/workers/configuration/routing/workers-dev/; `PUT /accounts/{id}/workers/subdomain`, https://developers.cloudflare.com/api/resources/workers/subresources/subdomains/methods/update/) | Installer creates one (earlier). A permission failure here is now `no_permission`, not a false "no subdomain" |
| 2 | R2 not enabled or no R2 plan (10042) | Removed as a dependency. Install goes on without the binding |
| 3 | Any other R2 error (5xx, scope refused) | Same |
| 4 | Several accounts, the first one forbids Workers | Installer tries each account and takes the first whose scripts it can list |
| 5 | All accounts forbid it (403, 10000, 9109) | `no_permission`, link to Workers |
| 6 | No account at all | `no_account`, link to sign-up |
| 7 | Rate limit 429 | `busy` |
| 8 | Cloudflare 5xx | `cloudflare_down`, link to status |
| 9 | Slow first deploy, no answer in 60 s | `not_ready`, link to Workers; Try again finds the script and continues |
| 10 | Script name `kiko` taken by something else | Already handled (`kiko-<hash>`) |
| 11 | Durable Objects on Free | Not a failure: Free supports SQLite classes (limits page above) |
| 12 | Authorization code expired or used | `oauth_failed`; Try again restarts the sign-in, which Cloudflare approves at once, and the install resumes |
| 13 | Email not verified | UNVERIFIED. No doc says the Workers API refuses it. Falls to `cloudflare_error` with a sentence and a Workers link |
| 14 | Unknown Cloudflare error | `cloudflare_error`: generic sentence and link, never the raw text |

## Design

One `FileBucket` interface (`apps/server/src/files/store.ts`) over R2 and `FileDO`. `fileStore(env)` picks R2 when `env.FILES` exists. Installer: bucket attempted only for a new script, `inherit` for an existing one (documented: an unresolvable inherit binding is dropped silently). Self-update sends `inherit`.
