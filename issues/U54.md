# U54 A status answer covers all work in progress

**Model** DeepSeek V4.1 Flash high. **Wave** 6. **Timebox** 60 min. **Port** 8854.

## Why

The U50 spike (`issues/evidence/u50/results.md`) showed that "what is the status?" is answered fast and never touches running work, but the answer usually covers only the lead's own current step. In case 10 a research worker was running and the lead answered "Adding that header now." The worker lines are already in the lead's input (`workers.note()` is rendered into each input by `core/agent/src/host.ts`), so the information is there. The prompt never says to use it for status.

## Do

1. Add one line to `WORK_LINES` in `apps/server/src/agent/prompt.ts`: when the human asks how things are going, cover everything in progress: what you are doing now, and each running worker from <context> with its step. Keep it one short line in the file's voice. No other product change.
2. Rerun the spike's status cases with a real model: `bun issues/evidence/u50/spike.ts` (read it to see how to select cases; add a case filter if there is none, inside `issues/evidence/u54/` as a copy, not by editing u50's evidence). Run cases 7 and 10 three times each on your own server, port 8854, dev keys from `apps/server/.dev.vars`.
3. Write `issues/evidence/u54/results.md`: each status reply verbatim, and whether it named every running worker with its step. Compare with the u50 numbers. Check that the status replies still trigger no `steer_work` or `stop_work`.

## Acceptance

Status names the running worker in at least 5 of 6 runs. `bun scripts/check.ts` green after merging `main`. If the wording does not hold, report the replies and stop; do not add structure.

### FAILED-BEFORE

u50 `results.md`, case 10, both runs: the status reply was "Adding that header now." and "File read done, now adding the header." Neither named the running research worker. The u50 spikes are the old-code evidence. In this spike, case 10 named the running research in 4 of 6 runs and gave its step in 2.

### Discoveries

The spike sends "what is the status?" four seconds after the lead first shows `typing`, which is often before the lead starts a worker. `runningAtSend` is 0 in every case-10 run and in half the case-7 runs. When no worker has started, `<context>` holds no worker line, so the lead answers with its own plan ("I'll kick off the test runner research"). That is the whole of the remaining variance: the wording names the worker whenever one is running at answer time. The wording is unchanged, per the brief ("do not add structure"). A future spike that sends the question only while a worker runs would measure the intended scenario directly.
