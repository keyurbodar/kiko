# U67 bash never loses a file across spaces

**Model** Claude Haiku 5.5 medium. **Wave** 8. **Timebox** 120 min. **Port** 8867.

Source: review E (`issues/review/E.md`) E2 (blocker) and E8. U51 has landed: `bash` now returns the paths each space's commit saved (`changed`), and every file tool reports through `details`. Keep that working.

## Do

1. **E2, blocker.** `apps/server/src/files/bash.ts` (the per-space commit, ~377-400 before U51; find it by `changed`) commits spaces in order. `mv /c.txt /home/m.txt` commits the chat space's removal even when the home space's write is refused (for example a lease or a concurrent writer), so the file is lost. Fix: commit every space's writes first; commit deletions only when every write saved. A refused write leaves the source in place. Reproduce first, as review E says: like `bash.test.ts` (~297), ada runs `echo keep > /c.txt`, then `mv /c.txt /home/m.txt; sleep 1` while bo writes `/home/m.txt`. Today `/c.txt` is gone and `/home/m.txt` is bo's. After the fix `/c.txt` survives. The test must fail on the old code (show the line).
2. Keep `changed` true to what was saved: a space whose write was refused reports nothing, and a deletion held back is not reported as changed.
3. **E8.** `apps/server/src/files/room-fs.ts` (~616-634, 691-705 before U51) has two-step commits that are dead since U22. Delete them, and refuse a batch that spans backends instead (one clear error). Test the refusal.

SCOPE: `apps/server/src/files/bash.ts`, `apps/server/src/files/room-fs.ts`, their tests, `docs/architecture.md` lines on bash commits.

## Acceptance

Each fix has a test that fails on old code. `bun run --cwd apps/server test -- bash`, `room-fs`, `workers` pass. `bun yuki verify files --url http://localhost:8867` and `bash` (if a suite by that name exists; `bun yuki verify --list`) pass, server plus suite in one heavy.sh call.
