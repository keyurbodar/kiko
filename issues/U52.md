# U52 A human never has to resend a message

**Model** Claude Haiku 5.5 medium. **Wave** 6. **Timebox** 75 min. **Port** 8852.

## Why

The owner's rule: a human message is never dropped and never needs resending. Known edges:
- The socket drops a text frame over `MAX_TEXT = 16_000` characters (`apps/server/src/room/socket.ts:27`, `:66`). Find what the human sees then, and whether the client composer stops it first.
- The agent inbox refuses an entry over 128 KB as `too_large` (`core/agent/src/inbox.ts:66`), and `REFUSED.human` (`apps/server/src/room/receive.ts`) tells the human to send a shorter one. Bursts are split at `MAX_DELIVERY_BYTES` (`apps/server/src/room/burst.ts:34`). Decide from code and a test whether a human message can reach `too_large` at all.
- `full` (500 open entries) is retried by the room: confirm it is retried without human action.

## Do

1. List every path where a human message can fail to reach the agent, with file:line and how it is reached. Write it in your report.
2. Fix each reachable one at the right edge, so nothing asks the human to resend. The expected fix for long text: the client turns a paste or message over the limit into an attached text file, the way the composer already sends files (`apps/web-solid/src/composer/`), and the message carries the file. Keep the composer instant and optimistic (AGENTS.md). If a server path is unreachable from a human, prove it with a test and delete the dead human branch rather than keep a notice no one can trigger. Keep the agent row of `REFUSED`.
3. Interface strings are sentence case.

## Acceptance

- A test that fails on old code for each fixed path.
- If you touched the client: `bun run --cwd apps/web-solid test` and typecheck, and one real-browser check with the `verify-yuki` skill (`.cursor/skills/`) that a 20,000 character paste sends as a file and the agent receives it. Your own vite port and your own server on 8852.
- `bun scripts/check.ts` green after merging `main`.
