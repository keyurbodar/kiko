# U85 Sign in with an access code

**Model** Claude Haiku 5.5 medium. **Timebox** 60 min. **Port** 8885.

The owner wants the deployed app usable without Google or GitHub: anyone who has a secret access code can sign in. No one without it can.

## Do

1. Server, new `apps/server/src/auth/access-code.ts`: a Better Auth plugin modelled on `devSession` (read the committed version: `git show main:apps/server/src/auth/dev-session.ts`; do not edit that file, the owner has local changes). One endpoint `POST /api/auth/access-code` taking `{ code, name }`.
   - Enabled only when the Worker has the secret `ACCESS_CODE` (add `ACCESS_CODE?: string` to `AuthEnv`). Without it, the endpoint answers 404 and `/api/providers` says `code: false`.
   - Compare the code in constant time (hash both with SHA-256 via `crypto.subtle`, then compare the digests byte by byte, or `crypto.subtle.timingSafeEqual` if available in workerd). A wrong code answers 401 with one fixed message, after the same work as a right one.
   - `name` must match `^[a-z0-9][a-z0-9-]{0,31}$`. The user is found or created by email `<name>@code.yuki` (so the owner and a friend get separate accounts by picking different names). Then create the session and set the cookie exactly as devSession does. Production only, so it is NOT behind dev-guard: it is a real sign-in method.
   - Register it in `createAuth` plugins when `env.ACCESS_CODE` is set, next to `devAuthPlugins()`.
   - `/api/providers` adds `code: true|false`.
2. Client, `apps/web-solid/src/app/sign-in.tsx`: when providers say `code`, show a small form: name and access code fields and one "Sign in" button (sentence case; match the screen's existing styles and components, Kobalte or @yuki/ui first). Submit with fetch to the endpoint, then reload to `/`. Show the server's message on 401. Keep the screen instant: the form renders from the providers answer it already waits on; do not add another request.
3. Tests: server tests in `apps/server/test` for: right code signs in and sets a cookie; wrong code 401; no `ACCESS_CODE` gives 404 and `code: false`; a bad name 400. Show the wrong-code test fails if the compare always returns true.
4. Docs: one line each in docs/architecture.md (auth section) and docs/product.md (sign-in), and AGENTS.md is unchanged.

Read /home/keyur/kiko/AGENTS.md and /home/keyur/kiko/issues/STANDING.md first (heavy commands through /home/keyur/kiko/issues/bin/heavy.sh, foreground; no full gate). Verify with the touched server tests, typecheck, check-rules, and `bun run --cwd apps/web-solid test` through heavy.sh.
