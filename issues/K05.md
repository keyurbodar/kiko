## Report

Partial. Units A, C and D step 1 are in code. Unit B is in code for the client, but its deletion waits for K04. The browser pass, the screenshots, the chat verify suite, and the docs are not done.

### What changed

- Long bodies clamp at 176px with a 28px fade and a visible "Show full message" or "Show less" text button. The toggle keeps `aria-expanded` and the scroll compensation.
- The agent and human bodies both draw from the server tree when one exists. A message without a tree falls back to plain text. Humans have no tree until K04 stores one.
- A masked link (its visible text names another host, or its href fails `isSuspiciousUrl`) renders as a button that opens `SuspiciousLinkDialog`, through the tree path.
- A file row is one button with the file icon, name, and size. Download stays in the files pane.
- The in-flow day pill is gone. A day change or a gap over 20 minutes leaves a time-only divider. The sticky chip is the only day cue, and `dateChipVisible` no longer checks for a divider at the top.
- The sticky chip labels older days as a short date ("May 13", or "Dec 31, 2023" from another year) instead of a weekday.

- DEVIATION: Unit D steps 2 to 4 (protocol `SystemEvent`, server writers, `SystemMessage` switch, `agent_message` grouping) not done. The brief says not to touch protocol event types.
- DEVIATION: The in-flow divider keeps its time-gap role and drops the day. The brief could be read as removing time-gap dividers too. I kept them, because a 20-minute gap cue is a time cue, not a date cue.
- DEVIATION: The masked-link rule adds a visible-host check to `isSuspiciousUrl`. R2 asks for "visible text names a different host". The check matches a host-shaped label, ignores a leading `www.`, and applies only to http and https.
- The harness `dayLabels` read now targets `chat-divider`, because `chat-day-label` no longer exists.
