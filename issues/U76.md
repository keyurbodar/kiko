# U76: fanout suite measures the calls, not the turn

## Report

STATUS: done. The suite now asserts on how many composio calls ran at once. The whole-turn budget is kept on its own. The prompt asks for one job.

BRANCH: s/u76-fanout-suite
HEAD: f1667ad64020e0fe1569af0542a250a2a32d80cc (code, with main merged in; this report is the next commit on the branch)

CHANGED
- apps/server/src/lib/dev-stats.ts: `inFlight(key, run)`, a dev-only counter that keeps the peak number of calls running at once until the next stats reset. Outside a dev build it runs `run` and nothing else.
- apps/server/src/integrations/composio/tools.ts: every composio call goes through `inFlight("composio.peak", ...)` inside the limiter, so queued calls do not count.
- apps/cli/src/verify/suites/fanout.ts: the wall/sum ratio is gone. Each turn asserts `composio.peak >= 10` (MIN_PEAK). The whole-turn budget stays at 60 s. The prompt now reads "Look up these N things on the web with Composio, as one job, and answer with one line per thing." The unused TOOL constant is removed.
- issues/U76.md: this report.

ROOT CAUSE OF THE OLD METRIC
- The ratio divided the whole turn's wall time, which includes model turns, by the sum of call times. A fully parallel run could still fail. The prompt also asked the talker for parallel `composio_search_web` calls, which only workers can make.

FAILED-BEFORE
- Not run: the old suite against a sequential server. The evidence that the old metric was wrong is U71's live run that failed at wall/sum 0.717 with its calls fully parallel (U71 report). The check that fails on the new code is the peak check, shown in the negative run above.

DEVIATIONS
- The suite is the test. The `inFlight` counter is dev-only and folds out of production, so it has no unit test of its own. The suite's negative run above is the check that it bites.
- Peak was chosen over the span (first start to last end). It needs one counter and it measures the thing asked for: calls that run together.
- The peak counter sits inside the limiter, so calls waiting in the limiter queue do not count. The negative run shows this: with limit 1, peak is 1 even though 20 calls were pending.
- The wall budget of 60 s is unchanged. The runs took 19 to 37 s per turn.
