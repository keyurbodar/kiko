## Rule for item 2

A deletion is in force only while two facts agree. The D1 tombstone says the account is being deleted. The DO mark names which start set it.

- `startDeletion` writes the tombstone first, then the mark. `rollbackDeletion` clears the tombstone first, then the mark. So a tombstone-free mark can only come from a rollback whose cancel failed.
- Jobs check the tombstone, then the generation. After a rollback the tombstone is gone, so a queued job stops even though the mark is still there.
- The socket, alarm, and room record check the mark first. The D1 read happens only while a mark is set, so normal traffic costs nothing extra. A mark with no tombstone is cleared on that same call, which re-arms the alarm.
- Retry already superseded the old mark, because `beginDeletion` overwrites it. This is unchanged.

Why this rule and not a login hook: a login hook would need a second cross-object call on every sign-in, and it would still leave the queued jobs current until the next sign-in. Reading the tombstone where the job runs closes both at once.
