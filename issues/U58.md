# U58 One migration helper: every table in its object's versioned list

**Model** Claude Haiku 5.5 medium. **Wave** 9. **Timebox** 150 min. **Port** 8858.

Source: review F (`issues/review/F.md`) F02, review G (`issues/review/G.md`) G05.

Today 32 source files contain `CREATE TABLE`, many created lazily inside methods (`user/credentials.ts`, `user-do.ts`, `agent/agent-do.ts`, ...). Two versioned lists exist: `apps/server/src/room/schema.ts` (in `transactionSync`) and `apps/server/src/user/schema.ts` (not atomic). `wakeups` is created in three places and `deletion_rooms` in two. Recent units added columns with `PRAGMA table_info` + `ALTER TABLE` because AgentDO has no list (`apps/server/src/room/burst.ts` pending columns, `core/agent/src/workers.ts` steps). The column fixture lacks `credentials` and `deletion_rooms`, and `agent-columns.test.ts` plus a `columns` op in `workers-worker.ts` duplicate the `schema-worker.ts` plus JSON fixture mechanism.

## Do

1. One `migrate(storage, list)` in `core/durable` that runs a versioned list inside `transactionSync` and records the version (generalize `room/schema.ts`'s). Each Durable Object (RoomDO, UserDO, AgentDO) calls it once in its constructor with its own list. Core packages that own tables (`core/durable` alarm `wakeups`, `core/agent` inbox/workers, `core/memory`) export their statements so the object's list includes them in order; keep the layer rules (`scripts/check-imports.ts`).
2. Move every `CREATE TABLE` / `CREATE INDEX` / `ALTER TABLE` into its object's list. Existing deployments must upgrade: an object already at version N runs only the new steps. A table that may already exist from a lazy create needs `IF NOT EXISTS` in the first new step; a column added by a past PRAGMA/ALTER needs a guarded step. Write the upgrade so a fresh object and an old object end in the same shape.
3. G05: one schema fixture. Extend `apps/server/test/schema-worker.ts` and `fixtures/schema-columns.json` to cover AgentDO and the missing tables, and delete `agent-columns.test.ts` and the `columns` op in `workers-worker.ts`.
4. A test: an object created with the old schema (seed the old tables by hand at the old version) migrates to the same columns as a fresh one.

Do not touch `apps/server/src/initiative/**` or `apps/server/src/user/initiative-loops.ts` (U66 is changing them); if one of them creates a table, list it as a follow-up instead. Do not edit `apps/server/src/auth/dev-session.ts`.

SCOPE: `core/durable/src/**`, table-creating code in `core/agent`, `core/memory`, `apps/server/src/**` (except the exclusions), `apps/server/test/**` schema tests and fixtures, `docs/architecture.md` lines on schema.
