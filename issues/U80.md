# U80: file tools and the changed-file list

## Report

STATUS: partial (owner cut scope to items 1 to 3 to ship now)

Items 1 to 3 are done. Items 4 (mv and rm/cp folder reporting), 5 (replay unsafe for mv and cp), and 6 (capped details) are not started and are left for a follow-up.

1. Changed paths are recorded at commit. `FilesOptions` takes a `touched(conversationId, paths)` callback. The factory passes `input.work.touched`. `saved()` and bash's exec wrapper call it. The `afterTool` path in `work.ts` is deleted. The false comment in `core/agent/src/workers.ts` is rewritten.
2. Bash stopped mid-commit. Bash's exec wrapper no longer calls `api.details` after a save, because a stopped call's details throw. Once the commit starts, `runCommand` runs it to its end. The "none of its changes were saved" error is only reported before the commit starts. When a stop lands during the commit, the output says which paths were saved.
3. `cp -r` uses `Promise.allSettled`. The result names the copied count and the first failure. Only the files that saved are recorded.
