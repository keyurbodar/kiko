# U51 Workers say what they changed

**Model** Claude Haiku 5.5 medium. **Wave** 6. **Timebox** 90 min. **Port** 8851.

## Why

When the human asks "what is the status" the lead answers from `workers.note()` (`core/agent/src/workers.ts:200`), which shows each worker's task and last step only. When a worker is stopped or fails, its report is only "stopped before it finished." (`workers.ts:261`). The human cannot tell what happened to their files. Every file write is atomic and `bash` saves per space all or nothing, so finished steps stay and nothing is rolled back. The human must be told which files changed.

## Do

1. Record, per worker, the paths its tools changed. The `work-steps` hook in `apps/server/src/agent/extensions/work.ts` already sees every tool call a worker makes. Take paths from the write-effect file tools' arguments (`write`, `edit`, `rm`, `mv` both ends, `cp` target, `mkdir`) only after the tool succeeded, if the hook can see the result; otherwise find the right point. For `bash`, record what the tool result says it saved (it names the spaces it saved). Do not parse shell commands. Store it in the workers table in a way that is safe to run twice (alarms and replays deliver at least once). Cap the list (say the first 20 paths plus a count) so a big job does not bloat the context.
2. `note()` shows, per worker: status, step count, files changed so far, last step.
3. The report of a stopped or failed worker states the files it changed before it ended, or that it changed none. A done worker's own report stays the model's; append the changed-files line only if it is cheap and short.
4. Keep `@yuki/agent` free of yuki imports (`scripts/check-imports.ts`). The path extraction is yuki behavior: pass it in as an option if the workers module is in core.

Delete anything this makes dead. No new concepts beyond the changed-files list.

## Acceptance

- A test that fails on old code: a fake worker writes two files and is stopped; its report and `note()` name both files.
- A replayed step does not duplicate a path.
- `bun scripts/check.ts` green after merging `main`. Run `bun yuki verify workers --url http://localhost:8851` and `bun yuki verify workers-model --url http://localhost:8851` with the dev keys and paste the result lines.
