- `answerAsks` now reads the run's bubbles before it checks for asks. It used to check the asks first. The cost is one query per run end, and the behavior is the same.
- `noProvider` is not covered by a workerd test. It needs a seeded room with members, and none of the existing room tests build one. Its wiring is covered by the `answerHeard` tests. Tests that call `answerHeard` cover the mail path the notice uses.
- The branch has a `wip:` commit (`f4eaa25d`) followed by a merge of `main`. I did not rewrite it, because STANDING item 4 forbids rebasing.

FOLLOW-UPS:
- A refused answer is no longer lost, but it is also not retried. `unanswered` only returns an ask when the askee hears the ask's message again, and that does not happen on its own. Refusals come from a human stop, the hop limit, or the delivery limit, so retrying may not help. The asker also still gets no notice. Someone should decide whether the room tells the human that an answer could not be delivered. That changes what a user sees, so it needs an owner decision.
- `Asks.answer` can still record a plain message from the askee to the asker as the answer of a closed ask, when that ask has no answer yet. That is existing behavior, and this change did not touch it.
